Pilar 02 — Ciclo de Vida 3D

El Bucle de Renderizado

requestAnimationFrame
El corazón de la aplicación es la función animate(), ejecutada a 60 cuadros por segundo:
function animate() { requestAnimationFrame(animate); const now = performance.now(); const delta = (now - lastFrameTime) / 1000; lastFrameTime = now; if (!isPaused) { updateOrbits(delta * timeSpeed); if (isNBodyMode) updateNBodyPhysics(delta * timeSpeed); } updateCameraTransitions(); controls.update(); renderer.render(scene, camera); }
Optimización de GPU: Se evita crear instancias new Vector3() dentro del bucle. Reutilizamos vectores globales estáticos para que el Garbage Collector del navegador no genere caídas de fotogramas (micro-stuttering).
Pilar 03 — Algoritmos Matemáticos

Motor Físico N-Body

Complejidad O(N²)
Atracción Gravitacional Cruzada Total
Cada astro influye sobre todos los demás
A diferencia del modelo kepleriano simple (donde solo el Sol atrae al planeta), el Modo N-Body calcula la suma vectorial de fuerzas entre todos los pares $(i, j)$:

$$\vec{a}_i = \sum_{j \neq i} G \cdot \frac{m_j}{\|\vec{r}_j - \vec{r}_i\|^3 + \epsilon} \cdot (\vec{r}_j - \vec{r}_i)$$
  • Parámetro de suavizado ($\epsilon$ / Softening factor): Evita que la aceleración tienda a infinito cuando dos cuerpos pasan extremadamente cerca, previniendo errores numéricos que expulsarían planetas a velocidades infinitas.
  • Integración de Velocidad Verlet: Método de integración numérica simpléctica que conserva la energía mecánica orbital del sistema a lo largo de miles de iteraciones.
Pilar 04 — Interactividad Espacial

Raycasting 3D con Precisión

THREE.Raycaster
¿Cómo sabe el código a qué planeta le diste clic?
Transformación de pantalla 2D a espacio 3D
  1. Captura las coordenadas del cursor $(x, y)$ en píxeles de la pantalla.
  2. Normaliza las coordenadas al espacio NDC (Normalized Device Coordinates) entre $[-1, 1]$.
  3. El THREE.Raycaster dispara un rayo matemático invisible desde la lente de la cámara que atraviesa la matriz del espacio 3D.
  4. Calcula la intersección geométrica esférica más cercana (raycaster.intersectObjects(bodyMeshes)) y extrae la metadata del planeta para pintar la telemetría en el HUD.

Q&A Técnico

Toca cada pregunta para desplegar la respuesta de programador Senior:

Respuesta Maestra: "Elegir Three.js y WebGL nativo fue una decisión deliberada de arquitectura: queríamos que Estelaris fuera 100% accesible en la web al instante desde cualquier navegador o teléfono móvil sin descargar ejecutables de varios gigabytes ni exigir tarjetas gráficas dedicadas pesadas. Además, nos dio control total a nivel de código sobre el DOM, el CSS y las fórmulas matemáticas sin las capas de sobrecarga (overhead) que traen los motores comerciales."
Respuesta Maestra: "En JavaScript, cada vez que haces new THREE.Vector3() o creas un objeto temporal en memoria, el motor V8 asigna RAM en el Heap. Si haces esto dentro de la función animate() que corre 60 veces por segundo para 17 cuerpos, creas miles de objetos por segundo. Eventualmente el Garbage Collector se ve obligado a pausar la ejecución del hilo principal de JS para limpiar la memoria, provocando caídas bruscas de FPS (lag spikes). Para evitarlo, usamos el patrón de Object Pooling / Vectores Reutilizables."
Respuesta Maestra: "Usamos un controlador centralizado de eventos keydown en el objeto window con control de estados booleanos. Verificamos si el foco está dentro de un input de texto para no interceptar teclas accidentales y usamos event.preventDefault() selectivo para teclas funcionales como F2, F4, F6, F7, F8, L o Espacio, garantizando una respuesta inmediata."
Respuesta Maestra: "Mediante carga asíncrona no bloqueante con THREE.TextureLoader y GLTFLoader basados en callbacks y Promesas. Mientras los recursos pesados descargan en segundo plano, la escena inicial y el HUD se renderizan inmediatamente con geometrías paramétricas de reserva, garantizando un tiempo de carga inicial instantáneo."
